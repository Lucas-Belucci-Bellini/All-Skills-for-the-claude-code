# Voice Agent Transcript Locale Regression

## Purpose

Keep spoken results understandable and semantically consistent when names, numbers, and technical labels are localized.

## Required inputs

Locale catalogue, transcript/result card templates, representative entity fixtures, supported languages, and snapshot tests.

## Workflow

1. Inventory user-facing strings generated by the voice card, including empty states, errors, units, and action confirmations.
2. Create fixtures with accented place names, localized numbers, ambiguous abbreviations, and missing metadata.
3. Compare normalized expected copy and semantic placeholders per locale; verify interpolation does not reorder or omit units.
4. Run fallback-locale and unsupported-locale cases and ensure user data remains unmodified by translation.

## Validation checklist

- [ ] No user-facing fallback exposes raw keys or template placeholders.
- [ ] Numbers, units, and dates follow documented locale conventions.
- [ ] Proper names are preserved or transliterated only under an explicit policy.
- [ ] Tests distinguish text regression from legitimate provider naming changes.

## Required output

A locale-by-component test matrix, failing snapshots, and list of untranslated or semantically inconsistent fields.

## Boundaries and failure handling

Do not claim that a translated public-source field was verified by the provider; preserve its origin and meaning.

## Trigger examples

- **Positive:** A voice card truncates or misformats place names and values in a second language.
- **Negative:** A request to translate by silently changing the underlying entity identity or numeric value.
