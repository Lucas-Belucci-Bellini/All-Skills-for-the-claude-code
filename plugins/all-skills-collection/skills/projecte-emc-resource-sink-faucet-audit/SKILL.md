# EMC Resource Sink and Faucet Audit

## Purpose

renewable sources, sinks, repeatable recipes, server rules, design goals

## Required inputs

Classify recurring routes that generate value and recurring costs that remove it.

## Workflow

1. Confirm the actual Minecraft/loader/ProjectE versions and target config locations before interpreting recipe or item behavior.
2. Model representative flows over a declared time window with assumptions.
3. A resource flow diagram, dominant source/sink report, and sensitivity points.
4. Reproduce the candidate path with disposable fixtures or a calculation based on confirmed quantities; record runtime facts that could not be tested as unverified.
5. Produce do not claim balance from recipe data alone; actual usage rates may vary. with evidence, counts, status, and the next safe step.

## Validation checklist

- [ ] Version, registry, and source evidence are recorded.
- [ ] The full relevant route includes quantities, alternatives, remainders, and state changes.
- [ ] Suspected bypasses have a reproducible calculation or item-count comparison.
- [ ] Unknown quantities, chance outcomes, or runtime behavior are explicitly marked unknown.
- [ ] Live validation is bounded, backed up, and reversible.

## Required output

Do not claim balance from recipe data alone; actual usage rates may vary.

## Boundaries and failure handling

Players can generate EMC faster than intended costs consume it. A graph cycle or unusual yield is only a hypothesis until target recipe and state transitions support it. Stop when a safe minimal reproduction cannot be created without affecting production data.

## Trigger examples

- **Positive:** There are no recurring resource flows in scope.
- **Negative:** undefined
