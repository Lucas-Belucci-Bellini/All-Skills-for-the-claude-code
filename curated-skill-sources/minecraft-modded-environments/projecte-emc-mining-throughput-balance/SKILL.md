# Mining Throughput Balance

## Purpose

tool stats, mining rules, ore distribution, yields, recipes

## Required inputs

Identify verified tool mechanics affecting resource acquisition in the target pack.

## Workflow

1. Confirm the actual Minecraft/loader/ProjectE versions and target config locations before interpreting recipe or item behavior.
2. Compare yield assumptions and EMC cost across tiers; separate measurements from estimates.
3. A mining throughput comparison with sensitivity and progression implications.
4. Reproduce the candidate path with disposable fixtures or a calculation based on confirmed quantities; record runtime facts that could not be tested as unverified.
5. Produce do not claim measured rates without measurements. with evidence, counts, status, and the next safe step.

## Validation checklist

- [ ] Version, registry, and source evidence are recorded.
- [ ] The full relevant route includes quantities, alternatives, remainders, and state changes.
- [ ] Suspected bypasses have a reproducible calculation or item-count comparison.
- [ ] Unknown quantities, chance outcomes, or runtime behavior are explicitly marked unknown.
- [ ] Live validation is bounded, backed up, and reversible.

## Required output

Do not claim measured rates without measurements.

## Boundaries and failure handling

A cheap transmuted tool greatly accelerates resource acquisition. A graph cycle or unusual yield is only a hypothesis until target recipe and state transitions support it. Stop when a safe minimal reproduction cannot be created without affecting production data.

## Trigger examples

- **Positive:** The task is unrelated to mining throughput.
- **Negative:** undefined
