# EMC Value Distribution Curve Review

## Purpose

tier labels, EMC values, material families, balance profile

## Required inputs

Create tier-specific distributions and show medians, outliers, and gaps.

## Workflow

1. Confirm the actual Minecraft/loader/ProjectE versions and target config locations before interpreting recipe or item behavior.
2. Compare curves by domain and explain differences that may be intentional.
3. A dataset and interpretation report with review candidates.
4. Reproduce the candidate path with disposable fixtures or a calculation based on confirmed quantities; record runtime facts that could not be tested as unverified.
5. Produce do not let statistics erase unique progression exceptions. with evidence, counts, status, and the next safe step.

## Validation checklist

- [ ] Version, registry, and source evidence are recorded.
- [ ] The full relevant route includes quantities, alternatives, remainders, and state changes.
- [ ] Suspected bypasses have a reproducible calculation or item-count comparison.
- [ ] Unknown quantities, chance outcomes, or runtime behavior are explicitly marked unknown.
- [ ] Live validation is bounded, backed up, and reversible.

## Required output

Do not let statistics erase unique progression exceptions.

## Boundaries and failure handling

A large EMC proposal set needs macro-level sanity checks. A graph cycle or unusual yield is only a hypothesis until target recipe and state transitions support it. Stop when a safe minimal reproduction cannot be created without affecting production data.

## Trigger examples

- **Positive:** Only one item is being changed with no comparison set.
- **Negative:** undefined
